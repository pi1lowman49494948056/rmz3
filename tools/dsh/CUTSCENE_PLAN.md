## 一、先修边界（空气墙）

**现象**：走到地图右边缘，角色掉下去死亡。

**定位结论**：
- 相机边界 `maxX = MAX_X`（`include/global.h:61`），MAX_X 极大，**没有按关卡实际宽度夹紧**。
- 所以地形走到尽头就是虚空，游戏本身**不自动生成空气墙**。
- 原版是靠地图边缘摆墙、或相机夹紧来挡的。

**方案（二选一或组合）**：
- A. `map.txt` 最右（和最左）列放实心 `#`，形成物理墙 —— 最简单，数据层就能做。
- B. 把相机的 `maxX` 改成地图真实右边界（相机夹紧，玩家走不出去）。

建议 **A + B 一起**：A 保证物理阻挡，B 保证镜头不飘。

## 二、位置触发对话（替换命中触发）

**现框架可直接实现**：
- 已有钩子 `DshStageUpdate`（挂 `sStageRoutine[2]`，每帧跑）。
- 现在它检查 `sDshEventPending`（命中时登记）；改为**检测玩家坐标是否进入触发矩形**即可。
- 触发一次后置标志，避免重复。

改动量：小（只改 `DshStageUpdate` 的判断）。

## 三、Zero 传送演出

**现成素材**（已确认存在）：
| 资源 | 说明 |
| --- | --- |
| `DM051_ZERO_UNK` | 传送前置 |
| `DM052_ZERO_TELEPORT_START` | 传送时仁王立ち |
| `DM053_ZERO_TELEPORT_END` | 传送后伏せ |
| `SE_TELEPORT`（330） | 传送音效 |
| `sprites/dynamic/zero/teleport/{start,end}` | 对应图块 |

**状态机**：`zeroTeleport()`（`src/player/zero/update.c:2227`），5 阶段：
0. 初始化（`gInTransport=TRUE`）
1. 跑向传送门（依赖 `gCollisionManager.teleportal`）
2. 播放 DM051→DM052
3. / 4. 后续

**关键发现**：**没有传送门时**，`zeroTeleport1` 第 2291 行 `else { done = TRUE; }`，
会直接跳过"跑向门"，进入 DM052 动画。

**结论**：可以**不放置传送门实体**，强制 Zero 进入 `ZERO_TELEPORT(10)` 状态
（`(z->s).mode[0] = 10; (z->s).mode[2] = 0;`）即可播放传送动画 + 音效。

需要验证：强制进状态后，动画结束后 Zero 的状态如何恢复（可能需要演出脚本接管）。

## 四、切房间

**入口**：`LoadStageRun(stageID, checkPoint)`（`src/stagerun.c:96`）——切关卡/重置关卡。
- 会重置 `gStageRun.id`、加载地形/敌人/脚本。

**门实体**：`SOLID_DOOR_2D_BLUE`(2) / `SOLID_DOOR_2D_GRAY_V`(20) / `SOLID_PHANTOM_TELEPORTER`(24)，
配合 `ZERO_DOOR_2D(5)` 状态。

**「新房间」有两种理解，需要定**：
- **A. 同一关卡的另一个区域**：只移动相机/传送玩家到另一片地形（不重载关卡）。
- **B. 另一个关卡**：调 `LoadStageRun(newStageID, checkpoint)` 重载。

建议 demo 先用 **A**（同关卡内传送，避免重载一堆状态）；真正跨关卡再做 B。

## 五、框架评估

| 需求 | 现状 | 工作量 |
| --- | --- | --- |
| 空气墙 | 无，需加 | 小（数据层） |
| 位置触发 | 钩子已有，改判断 | 小 |
| 两段对话 | 已有（lock+message+wait+release） | 无 |
| 传送动画 | 素材+状态机现成，需强制触发 | 中 |
| 切房间 | LoadStageRun 现成，需接演出 | 中 |

**结论：能直接做，不需要大改框架。** 主要是把「命中触发」换成「位置触发」，
再串一段演出脚本（lock → 两段对话 → 强制传送 → 切房间/移动相机 → release）。
