# Demo 地图配置自动同步（0.9.8）

## 日常只编辑两个文件

- map.txt：每字符16×16像素；`.`空，`#`实心。宽是15的倍数，高是10的倍数。左上为原点。不允许空行或未知字符。
- room.json：房间位置、左右墙厚度、玩家出生点、传送触发位置及落点。

room.json 坐标说明：
- origin_chunk：[列,行]，每个chunk是240×160像素，放在32×13关卡网格内。
- wall_columns：左右实心墙的格数；工具检查墙体，不会自动补画。
- spawn_px：[X,Y]，相对房间左上角的像素坐标；Y是脚底对应的地面顶端，必须16对齐。
- teleport.trigger_left_px：相对房间左边的X，站在此位置以右开始触发。
- teleport.target_px：相对房间左上角的落点，格式同出生点。

当前示例：地图300×20格，origin_chunk=[0,9]；出生[1312,288]对应世界[1312,1728]。
扩高时如果想保持原来的地板位置，要同时调整origin_chunk和两个落点的相对Y；工具不会猜测你的关卡意图。

## 使用

在工程根目录运行（使用已安装的Python 3，无第三方库）：

```text
python tools/dsh/map_editor.py
python tools/dsh/map_editor.py --check
```

第一条验证并同步；第二条只检查，不写文件。然后按现有构建流程编译rmz3.gba。
只编辑map.txt但不运行同步命令不会更新游戏。普通make不会自行执行Python生成器。

## 自动生成

- screen.bin：15×10分屏、相同屏去重，保护装饰层共享chunk。
- sChunkMap1：放置新房间，清除旧地形范围。此工具将spacecraft作为专用Demo，不保留其余区域的可玩地形。
- sScreenBehavior：新房间设为已验证的0x0102，房间外设为虚空。
- sTilesetOffset：新房间使用已验证的0x01素材组合。
- Camera_0834d268：从房间范围和墙厚推导相机边界。
- Entity_ZeroSpaceCraftStartPoint：转换出生坐标。
- include/dsh_room_config.h：传送触发区域、落点与镜头高度，C代码不再写死数值。

生成前全部验证；数据错误不会写出一半结果。文件替换逐文件进行，运行期间不要同时构建或让其他AI修改输出文件。
重复生成结果一致；没变化的文件不会重写。makefile已补充脚本include和生成头文件依赖。

## 限制

这是当前Demo的安全子集，不是任意关卡生成器：仅空地/实心、封闭左右墙和底部、一个出生点和一次传送；暂不导入美术、不生成敌人、不支持特殊地形或多个房间。
配置不改变原始数组大小，不新增关卡槽。固定chunk池不足会报错，不会静默覆盖别的资源。
出生和落点检查为16像素宽、32像素高的保守站立空间，仍需模拟器验证实际角色动作。
工具不会自动判断整张地图是否可通关。

baseline/是0.9.7的固定地图资源分配基线，供确定性生成和共享图块保护。不要随意修改或重新覆盖；以后更换素材体系时需要显式升级基线。
不要手改生成的数组/头文件，下一次同步会覆盖它们。
